OrderSection is one order of a print: "Bestelling 1" or "Nabestelling {n}". A print always has order 1; a Nabestelling is added when a klant wants more of a project or a part broke. An order has its own items, Verkoopprijs, payments, write-off and, from M7, its own invoice line.

**Anatomy.** `<details class="pp-order">` inside `.pp-orders` (a column, newest order first). **Summary** (`summary`, 44px high on phones, whole row is the toggle): `.ttl` with the title and the date, `.sum` with the status badge, the order total (`pp-money`) and, for a partly paid order, `pp-remaining` "Nog € x open"; `.chev` rotates when open. **Body** (`.bd`): on desktop (`pp-detail`, two columns) the left column holds AssetListItem rows with "Aantal keer geprint" for this order (the same file may appear again in a later order) and CostBreakdown, the right column the PaymentPanel; on phones everything stacks. Orders that are settled (Betaald or Afgeschreven) are closed by default (`details` without `open`), unsettled ones open; the newest unsettled order has `.is-open-order` (`primary` border). **Delete:** "Nabestelling verwijderen" (ghost, bottom of the body; Admin and Editor) is shown for a Nabestelling only while it has no payment, no write-off and (from M7) is not on an invoice; otherwise it is disabled with "Staat op factuur {nummer} en kan niet worden verwijderd." or hidden when payments exist. Bestelling 1 has no delete action. Deleting asks ConfirmDialog "Nabestelling {n} verwijderen?"; the files return to "Niet in een bestelling" in the same project folder. **Payment rules inside an order:** a payment is at most the open remainder; "Betaling ongedaan maken" (Admin only) reverses the most recent payment of this order; undone payments stay in the history (see PaymentPanel).

**Tokens.** `surface`, `border`, `primary`, `radius-lg`, `space-3`, `space-4`, `motion-base`, `muted`, status badge tokens.

**States.** Settled and closed, open with open amount, open and deletable, locked by invoice, focus-visible (summary), reduced motion (no chevron animation).

**Accessibility.** `details` and `summary` give the toggle role and keyboard support (Enter, Space); the summary text reads title, date, status, total and remainder; the focus ring is 2px `focus-ring`; the chevron is decorative (`aria-hidden`).

**Dutch copy.** Bestelling 1 | Nabestelling {n} | {datum} | Nog {bedrag} open | Nabestelling maken | Nabestelling verwijderen | Staat op factuur {nummer} en kan niet worden verwijderd. | Een nabestelling zonder betaling kan worden verwijderd. De bestanden gaan terug naar "Niet in een bestelling".

**Order date (1.5).** The date in the header is the modification time of the newest counted G-code in the order, else the date the order was created. It is the Datum column on invoices and the date the Van / Tot en met filter works on. Days open count from the invoice date, else the date the Verkoopprijs was set, else the order date. On the PDFs one invoice line is made per order: Bestelling 1 shows the print name, a Nabestelling reads "{print} (nabestelling {n})".

**1.6.** (2026-10-07) **Locked order (GAP-048).** A section whose order is on a final invoice shows the badge "Op factuur {nummer}" in its header; inside, the price field, "Aanpassen", "Aantal keer geprint", the toggle "Telt niet mee in kosten" and the spool pickers are locked as described in PaymentPanel, CostBreakdown and AssetListItem, with one `.pp-lockhelp` line above the file list. Payments and write-offs still work. **"Spoel voor de hele print"** skips locked orders: it changes the spool (and so the cost), so a locked order keeps its spools; the result toast names the reason: "Spoel gewijzigd in {n, plural, one {# bestelling} other {# bestellingen}}. {m, plural, one {# bestelling} other {# bestellingen}} overgeslagen: staat op een factuur." (key `spool.wholePrintSkipped`).

**1.9.** (2026-10-07) **One card with sections (GAP-074, resolved).** The order is **one** bordered card (`pp-order`, `radius-lg`, `border`); everything inside it is a *section*, not a card. Rule per level: **order card** has the only rounded border; **section** (Bestanden, Totaalkosten, Betaling) has no border, no radius, no ground of its own, and is divided from the previous section by a 1px `border` hairline (top edge); **row** (a file, a cost line, a payment line) is divided by a hairline as before. Section padding is `space-4` on the sides (`space-3` at 480px and below) and the cost table's first and last cell use the same side padding, so the table reads as part of its section (it had `space-3` against a `space-4` header). Nothing sits against the rounded corners: the header row and the first section keep `space-4` from the edge. **Columns:** 901px and up the order body has two columns (Bestanden and Totaalkosten on the left, Betaling on the right) split by a vertical hairline; 900px and below one column in the order Bestanden, Totaalkosten, Betaling with horizontal hairlines (so cost and payment no longer land side by side on a tablet). The preview draws 360, 768 and 1280px. Alerts inside an order (such as the new-files notice) get `space-4` margins above the body. **Breaking (visual):** `.pp-card` inside `.pp-order` is flattened by CSS (border, radius, ground removed); a `.pp-card` inside an order that must stay a card has to leave `.pp-order` (nothing in the system does). **Changed classes:** `.pp-order .bd` (padding 0, gap 0), `.pp-order .pp-detail`, `.pp-order .pp-pay` (no 420px cap).
