BulkDialogs are what the buttons "Spoel toewijzen" and "Prijs instellen" in BulkActionBar open. Both work on the selected prints, report a result per print and never block the prints that can be updated.

**Anatomy.** **Spoel toewijzen aan {n} prints** (Dialog, 440px, bottom sheet on phones): one line of explanation, the SpoolPicker list (search, spool swatch, name, price per kg; the last option "Geen spoel" removes the spool) and the primary "Toewijzen". It sets the spool for the whole print on every selected print; files and slots that have their own spool keep it. **Prijs instellen voor {n} prints:** one radio group: "Dezelfde prijs voor elke print" with a Verkoopprijs NumberInput (every print gets that price, it is not a total that is split), or "Voorstel uit marge per print ({marge}%)", which gives each print its own suggested price; prints without costs are skipped. The price is set on the **newest order** of each print; if that order is already paid or written off, or is locked by an invoice, that print fails with a reason and the others continue. **Result:** the dialog closes and a Toast "{ok} van {totaal} bijgewerkt" appears; when there were failures a `warning` alert (`role="alert"`) stays above the grid, titled "{n} prints niet bijgewerkt", with one `.pp-results` line per print: name and reason. Reasons: "Nabestelling {n} is al betaald.", "Nabestelling {n} is afgeschreven.", "Staat op factuur {nummer}.", "Deze klant wordt niet gefactureerd.", "Kosten ontbreken.", "Geen toegang." While the call runs the button shows a spinner and both buttons are disabled.

**Tokens.** Dialog, SpoolPicker, FormField, NumberInput, Radio, Alert, Toast tokens. Classes `pp-results`, `pp-picker`.

**States.** Default, saving, all ok (toast only), partial (toast and alert), all failed (alert only, no toast), error (inline alert, nothing changed).

**Accessibility.** Dialogs follow Dialog; the alert is `role="alert"` and is moved to by focus after closing; the result list is a real `ul`; the toast is `role="status"`.

**Dutch copy.** Spoel toewijzen aan {n} prints | De gekozen spoel geldt voor de hele print, op elke geselecteerde print. | Bestanden en slots met een eigen spoel houden die. | Toewijzen | Prijs instellen voor {n} prints | De prijs komt op de nieuwste bestelling van elke print. | Dezelfde prijs voor elke print | Voorstel uit marge per print ({marge}%) | Prints zonder kosten worden overgeslagen. | {ok} van {totaal} bijgewerkt | {n} prints niet bijgewerkt

**2.9.** (2026-10-17) **Absence is the last option, never a separate action (GAP-138, resolved) — and a third dialog joins these two.** `Status instellen` in BulkActionBar opens a dialog of this family, built and verified on three prints at once with axe 0, and it settles a pattern this component had been following without stating: **"Geen spoel" has been the last option of the spool list since 1.4, not a remove button**, and the status dialog is built the same way — four radios, one of them **"Geen status"**.

**That is the rule for every bulk dialog from here, and the reason behind it is the owner's.** He asked for the fourth option because **a state must always be able to go back — a klant can change their mind about one print**; the pattern argument below is mine and secondary, and I first credited the decision to the person who built it rather than the person who made it. Clearing a value is **setting it to none**: the same control, the same confirmation, the same result shape, one line in the report rather than two kinds of line. A separate "wissen" action would split one act into two, would need its own result wording and its own failure reasons, and would present a destructive-looking control for something that destroys nothing and is as reversible as any other choice. Where a value can be absent, absence is an option **in the list**, placed last.

The rest of the contract is unchanged and the status dialog follows it in full: one result per print, the toast "{ok} van {totaal} bijgewerkt", the `warning` alert "{n} prints niet bijgewerkt" with a `.pp-results` line per print and its reason, locked and invoiced prints failing individually while the others continue. No new class, token or copy key from this entry.
