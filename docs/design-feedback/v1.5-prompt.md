The 3D Prints Portal design system (version **1.4**) is now implemented, and milestone 7 (invoices, credit notes, Openstaand, PDFs) is built on top of it. Thank you for v1.4: GAP-029 to GAP-036 are implemented as delivered. While building M7 and checking v1.4 in the browser, the developer found the gaps below. Please update the design system to resolve them.

For each gap:

1. **Decide.** Resolve it, merge it with another gap, or reject it with a reason. Ask me if a gap needs a product decision.
2. **Resolve within the system.** Prefer existing tokens and components. Add a new token or component only if it is genuinely needed, and name it consistently with the existing scheme. Don't rename or remove existing tokens unless the gap requires it. If you must, list every breaking change.
3. **Deliver completely.** Give values for both light and dark themes, all states, phone and desktop layouts where relevant, Dutch copy, and contrast ratios for any new colour pair (WCAG 2.2 AA).
4. **Update the hand-off deliverables:** `tokens.css` (and JSON), `components/bundle.css`, the affected component specs and screens, the copy deck and the contrast report.
5. **Export complete READMEs.** In the 1.4 zip, 18 component READMEs contained only their new "1.4" paragraph (GAP-038). Every README in the export must hold the full spec (anatomy, tokens, states, accessibility, Dutch copy), with the change for this version folded in or added as a dated paragraph.
6. **Every class a preview uses must exist in `components/bundle.css`.** v1.4 previews use `pp-text-lg`, `pp-text-xl` and `pp-text-2xl`, which are not defined (GAP-039), and the DatePicker calendar is styled only by the preview's own `<style>` block (GAP-043). Please check all previews for classes with no rule.
7. **No raw values in screens.** The app may only use tokens and the classes in `components/bundle.css`; it cannot copy inline `style="…"` values from the previews. v1.4 cleaned the M6 and M7 previews. Please now clean the previews milestone 8 needs: **ScreenShareLinks, ShareLinkRow, ScreenSharePage (billed and niet-factureren variants) and DocOverview**, plus the loading skeletons and ScreenInvoices' remaining `font-size:12px`.
8. **Check widths.** Look at every changed dialog at its real width (440px, `pp-dialog.sm`) and every screen at 360px and 1280px, not inside a wider preview frame (GAP-045 was hidden by a 600px frame).

**Priority:** GAP-043, GAP-041, GAP-040 and GAP-042 first; they block features in daily use. Then GAP-037 and GAP-046, and then the small fixes (GAP-038, GAP-039, GAP-044, GAP-045).

Finish with a **changelog for the new version (1.5)**:
- a table `GAP-### → resolved / merged into GAP-### / rejected (reason)`;
- new tokens, changed tokens, new or changed classes, components and screens;
- breaking changes, if any.

Product decisions taken since v1.4 that affect the design (use them when resolving the gaps):

- **One invoice line per order.** Bestelling 1 shows the print name; a Nabestelling is "{print} (nabestelling {n})" on the PDFs.
- **Order date.** An order's date is the modification time of the newest counted G-code in that order, else the date it was created. It is the Datum column on invoices and the date in the OrderSection header, and the Van / Tot en met filter works on it.
- **Days open** count from the invoice date, else the date the Verkoopprijs was set, else the order date.
- **Payment reference.** A final invoice uses its number; a Concept and a Herinnering use the klant name.
- **Finalising** fixes the price: a "Voorstel uit marge" becomes the order's Verkoopprijs. After that the price, cost adjustments and "Aantal keer geprint" are locked ("Op factuur {nummer}"); payments and write-offs still work.
- **Credit notes** (Admin) write off the credited amount only up to what is still open; what was paid stays paid (refunds are not tracked).
- **Openstaand for Users:** read-only, only the klanten they were granted, no buttons.
- **Logo:** PNG or SVG upload (max 1 MB); the app stores and serves a PNG only. It replaces the studio name on documents **and in the AppShell** (sidebar, and wherever the brand appears); see GAP-046.
- **PDFs** use the built-in Helvetica font (Western European characters only).
- **Reindex** still waits for the result; the progress bar ("Indexeren… {n} van {totaal} bestanden") needs indexer progress that does not exist yet. No design change needed.

Open gaps. GAP-038 has an approved reading (1.3 README plus the 1.4 paragraph); on all others the owner chose to wait for the design system, and none has a temporary placeholder. For GAP-045 the app lets the button row wrap, right-aligned, using existing classes only.
